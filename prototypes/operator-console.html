Scenarios

Each one forces a case that is hard to judge on paper. Flip variants with the bar at the bottom to see how each renders it.

Presets

Momentary, arm-set-only, reverts on unkey (ADR-0013).

Keying

  • Hold ` - momentary
  • Shift+` - toggle latch
  • On-screen key is a second input source; both report level + liveness

What this prototype fakes

  • No audio, no WebRTC, no server. Talkers are simulated on a timer.
  • Staffing state is derived here (occupant of a staffing role, subscribed, unmuted, healthy) so ADR-0005 can be seen working, not asserted.
  • Audience is computed per (role, user) from a fixed roster of 16 occupants.
  • The permission grid is fixed: this session is Flight Director and its reach is the 20 loops shown. Loops outside reach do not exist here.
  • Volume is a slider that changes nothing. Loudest-wins overlap is not simulated.
  • Announcements, breakout, admin console and access requests are all out of scope for this prototype.

Things to look for

  • Can you tell armed but not subscribed from subscribed but not armed at a glance?
  • Does a hot latch survive being ignored?
  • Does away read differently enough from vacant to stop a wasted transmission?
  • When the state freezes, is it obvious that what you are reading is old?
  • At 20 loops, which variant is a wall?
