# A priority transmission is marked wherever it lands

[ADR-0046](./0046-priority-is-keyed-not-held.md) gave the talking indicator a priority variant and called it the entire answer. It grounded that on explanation: priority changes the audio at fire time with nothing on screen having changed first, so the mark exists to explain the gain change while the gain change is happening. This ADR keeps the mechanism, replaces the grounding, and settles the two cases the explanation reading gets wrong.

**Priority is a declaration, and the declaration is the point.** Read as an explanation, the mark is pointless where there is no anomaly, and it would render only for receivers who happened to have that loop turned down. That makes the signal an accident of personalisation. Somebody keyed the only override in the system to say *this is urgent*; that is worth seeing on a loop you had at full volume, where it changed nothing you heard.

**A muted loop shows it too.** This is the case ADR-0046's grounding could not reach: mute means no audio at all, so there is no gain change to explain, and yet it is the loop where an urgent transmission matters most. `CONTEXT.md` already keeps loop health and talking indicators arriving on a muted loop because the subscription stands. The mark is a talking indicator with a modifier on it. It grants nothing, unmutes nothing and can be ignored with no consequence, which is the test a hail passed in [ADR-0047](./0047-a-hail-is-a-monitoring-directive-without-the-authority.md), so it is not the compelled attention [ADR-0035](./0035-a-monitoring-directive-promotes-a-loop-it-does-not-police-it.md) and [ADR-0045](./0045-priority-defeats-attenuation-and-nothing-else.md) both refused. Suppressing it would make mute quieter than it advertises: an operator asked for silence, not blindness.

**It names nobody**, so [ADR-0033](./0033-the-console-shows-that-someone-is-talking-never-who.md) is untouched. Priority is a property of the transmission, not of the person, which is exactly what [ADR-0046](./0046-priority-is-keyed-not-held.md) established when it refused to make priority an attribute of anyone.

**The mark lives exactly as long as the attribute, with no floor.** A press has no minimum duration, deliberately, because abuse looks like a hundred short jabs (ADR-0046), and the attribute rides signalling so it can arrive after the audio (ADR-0045). A sub-second press therefore renders for a moment or not at all. A floor of a second or two would fix that and would make this v1's first transient event, a shape the map has refused twice, most recently when a hail turned out not to need one. Not worth it for the case it buys.

## Consequences

- **A sub-second priority press can leave no trace on any console.** The audit log is then the only record it happened, which is why ADR-0046 audits every press with no minimum threshold and records the armed loop set with it. Stated here rather than left to be discovered by whoever first asks *did that just happen*.
- **Every loop card must carry the mark as a word**, alongside staffing state and the talking indicator it already holds ([ADR-0032](./0032-the-console-is-two-views-of-one-loop-list.md)). The board is where the space runs out, not the ledger.
- **The first moments can play attenuated and unmarked.** ADR-0045's signalling race applies to the mark as well as to the gain, and both resolve together because they are one fact arriving.
- **This is the only thing a receiver learns about a transmission beyond that it is happening.** [ADR-0057](./0057-the-receiver-is-never-told-where-else-a-transmission-went.md) refuses to tell them where else it went, because reach changes nothing they hear. Gain and urgency do. Any later proposal to surface something about a transmission has to clear that line.
- **An ungated priority key that degrades to nothing now degrades visibly.** ADR-0046 accepted that if everyone keys priority always, priority means nothing. The mark showing everywhere makes that decay observable on the console rather than only in a log nobody reads.
