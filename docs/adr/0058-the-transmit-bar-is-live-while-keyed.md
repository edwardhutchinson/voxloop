# The transmit bar is live while keyed, and the latch is never taken out of your hand

[ADR-0034](./0034-the-transmit-bar-is-always-visible-and-the-audience-is-a-count.md) made the transmit bar answer *who am I about to talk to*, read in the second before keying. That leaves the seconds after it. An arm set can change while the key is held, and an operator who read the bar a moment ago is now wrong about where their voice is going. So the bar stays live: the armed set renders while keyed, not only before.

With [ADR-0057](./0057-the-receiver-is-never-told-where-else-a-transmission-went.md) refusing the receiving side anything, this is the whole of VoxLoop's compensation for multi-destination emission.

**Only a change this session did not ask for is marked.** A preset momentarily replaces the arm set while keyed and reverts on release ([ADR-0013](./0013-arming-is-independent-of-subscription.md)), which makes it a mid-key change by design and the most routine one in the system. Marking it would fire the signal constantly and train the operator straight past it, which is how ADR-0034 already reasoned about the latch banner becoming chrome. A deliberate arm is the same. What gets marked is a change the operator's own hand did not make: an administrator pulling an `emit` cell mid-transmission, and anything later that moves an arm set from outside the session. Provenance is the rule and it costs one flag on the update, because the server applies both kinds and knows which is which.

**At zero armed the latch stands.** A revocation can empty the arm set outright, leaving somebody keyed with nothing routing, talking into a dead mic believing they are live. That is [ADR-0005](./0005-occupancy-means-listening-not-signed-in.md)'s misrepresentation with the stakes raised. Releasing the latch for them is the obvious fix and it is wrong: ADR-0034 already ruled that a zero audience never blocks a transmission and that the console does not overrule an operator about their own operation. Taking the key out of somebody's hand mid-sentence is a bigger lie than showing them an empty arm set. The key control renders differently at zero armed instead, the way a card names a blind-armed loop in words rather than relying on a border.

**No third audience count.** Priority applies to the whole arm set ([ADR-0045](./0045-priority-defeats-attenuation-and-nothing-else.md)) and the server holds every subscriber's volume, so the bar could say *3 of 6 have this turned down*. It does not. The number would sit beside `present, not hearing` and be read as another flavour of it, and volume is personalisation persisted precisely because it is safe to be stale ([ADR-0050](./0050-personalisation-persists-what-is-safe-to-be-stale.md)), so it can be wrong. While the priority binding is held, the bar states the armed set as priority's scope. Loops, not a number nobody can interpret in the second before keying.

## Consequences

- **The bar answers two questions with the same words**, *who am I about to talk to* and *who am I talking to*. No second control, no second wording, and ADR-0034's never-scrolled-away rule now carries more weight than it did.
- **Blind-armed loops earn their cost here.** ADR-0034 names them in words on the strength of the pre-key read; the live bar is the moment that naming actually pays.
- **This is the third place the console renders provenance**, after [ADR-0016](./0016-displayed-state-is-observed-or-asserted.md)'s observed-or-asserted split and the directed subscription's marking of who put it there. Same principle each time: a state somebody else moved must not look like one you set.
- **A wide arm set is still ungated.** Nothing here stops an operator arming twenty loops and keying them, and nothing should; the bar makes the reach legible and the decision stays theirs, consistent with ADR-0034 refusing to interpose a dialog on a zero audience.
