## The product in one page

An operations centre runs on voice. VoxLoop is the software that carries it.

A **loop** is an audio conference and the only thing voice can be addressed to. A **role** is a staffable position — `Flight Director`, `Support Engineer` — that carries permissions. A **user** is a person, who carries only *eligibility* for roles and their own *personalisation*.

Voice authority is one grid: each **(role, loop)** pair holds a single **permission** from an ordered four — `none`, `monitor`, `emit`, `control` — and there is no second layer, no per-user exception and no override. "Who can hear loop X" is column X. "What can this person reach" is their role's row.

A person **signs in** to the application, then **assumes** a role, which creates their **session**. From the console they **subscribe** to the loops they want to hear, **arm** the loops they might speak to, and **key** to speak. A loop's **staffing state** tells anyone about to key up whether a human is demonstrably hearing it.

The whole thing runs on one box inside the customer's network, with no external runtime dependency.

## Standing requirements

These constrain every feature. A change that breaks one of them is not a trade-off to weigh; it is a defect.

**Displayed state is factual.** The brief's sharpest requirement, and [ADR-0016](../adr/0016-displayed-state-is-observed-or-asserted.md) makes it checkable rather than aspirational. Every state item is **observed** (the server saw it) or **asserted** (a user claimed it), the console may not render the two alike, and **optimistic rendering is banned outright** — a local action may change local audio, never the displayed state of the world. Every toggle visibly lags a round trip. That is the cost, and it is the cheapest honesty available.

**Cognitive load is the thing being minimised.** There is already a lot going on in a control room. Minimal, muted, professional; a clean sheet with no obligation to echo existing hardware. Motion is permitted in exactly one place ([ADR-0033](../adr/0033-the-console-shows-that-someone-is-talking-never-who.md)).

**A card cannot hold a sentence.** Anything the model requires must fit the **board** as a word, and may be a sentence only in the **ledger** ([ADR-0032](../adr/0032-the-console-is-two-views-of-one-loop-list.md)). This is the standing constraint on every state added from here.

**Self-hosted, with no external runtime dependency.** Possibly air-gapped. No phone-home, no hosted service, no mail path, no CDN.

**The recording seam stays open.** Recording is not v1 and is coming. A new sink must attach **without touching the media path or loading the media server**, and per-talker streams must survive server-side ([ADR-0009](../adr/0009-recording-taps-plain-rtp-on-loopback.md)). This rules out peer-to-peer mesh and end-to-end encryption.

**Later work must not be foreclosed.** Transcription, keyword-triggered workflows and stream processing are out of v1 and must not become expensive to add. They consume the same seam.

## 1. The model

### Users, roles and loops

A **user** is an account belonging to a person. A user is never a destination for voice and carries no operational permissions of their own ([ADR-0002](../adr/0002-permissions-attach-to-role-and-loop.md)).

A **role** is a staffable position with a `max_occupants` limit. Single-occupant and multi-occupant roles are the same concept under different limits. A role carries permissions and a **role default** console; it is not a group of users.

A **loop** is an audio conference — a many-to-many bus, never a person, never a role, and **the only destination for voice** ([ADR-0001](../adr/0001-the-loop-is-the-only-destination.md)). There is no user-to-user calling and no way to address a role with voice.

### The grid

One value per **(role, loop)**, from an ordered four, each rung carrying those below ([ADR-0011](../adr/0011-a-permission-is-one-cell-on-the-grid.md)):

| Rung | Confers |
|---|---|
| `none` | nothing. An absent cell is `none` |
| `monitor` | may subscribe and hear |
| `emit` | may arm, key, key priority, hail, and use presets |
| `control` | **operational authority** on that loop ([ADR-0012](../adr/0012-operational-authority-is-the-control-rung.md)) |

Evaluation is one lookup. There is no per-user grant, no per-user deny, no explicit deny beating a grant, and no precedence rule. Listen and emit are deliberately **not** independent axes: emit-without-monitor is a hazard, and the one genuine case for it is a **service principal**, which is not a role.

**Granting one person one extra loop always costs a role.** There is no per-person patch and there never will be.

A **permission change applies to live sessions immediately.** Revoking `emit` cuts a transmission mid-word; revoking `monitor` drops the subscription and says why.

### Eligibility

**Eligibility** is the unconditional grant permitting a user to assume a role. It carries no permissions of its own. Revoking it while the user occupies the role ends their occupancy immediately, with the reason shown.

**Reach** — the loops a role may monitor, emit to or control — belongs to a **(user, role)** pair and is **never composed across roles** in a session or in the admin console. A session is bound to one role, so a person's reach is only ever one row's worth at a time ([ADR-0015](../adr/0015-the-admin-console-reads-one-row-at-a-time.md)). The **lobby** is the one place reach is composed, and it survives that objection because in the lobby the user holds no authority at all ([ADR-0023](../adr/0023-sign-in-is-to-the-application-and-a-role-is-assumed.md)).

### Staffing

A **staffing role** is a role marked as counting toward a loop's **staffing state**. It is set per (role, loop), only where the role holds at least `emit` on that loop — a role that cannot answer cannot staff.

**The flag reports; it never subscribes** ([ADR-0065](../adr/0065-the-staffing-flag-reports-it-never-subscribes.md)). Marking a role as staffing a loop puts nothing on any occupant's console. [ADR-0052](../adr/0052-a-role-default-is-a-starting-point-never-a-floor.md)'s **role default** is the only thing that seeds one, and an auto-subscribe firing at every assume is the re-imposition it rejects. No seeding rule could close the gap anyway: the grid only ever narrows within reach, so it never reaches a user who has already personalised. The answer is visibility instead, in §8 and the lobby.

Staffing state answers *is a human behind this loop*, and it is computed across **every occupant of every** staffing role for that loop. There is no partial value.

| Value | Meaning |
|---|---|
| `staffed` | an occupant of a staffing role is **demonstrably hearing** it |
| `away` | such occupants exist, none is hearing it. Always carries the reason: **not subscribed**, muted, off console, unreachable, or not receiving the beacon. Counted across occupants where they differ |
| `vacant` | nobody occupies a staffing role |
| *(nothing)* | the loop has **no staffing roles configured**. Rendered blank, not as a fourth word ([ADR-0056](../adr/0056-a-loop-with-no-staffing-roles-has-no-staffing-state.md)) |

Every newly created loop starts with no staffing state. A loop can lose its staffing state when the last staffing role is removed; the console must not treat that transition as an error.

**`away — not subscribed` can stand indefinitely.** It is the one reason meaning nobody set the console up, rather than somebody stepping away, and nothing in VoxLoop forces it closed. Stated on the card, in the ledger and in the lobby; see [§16](#16-accepted-gaps).

A **service principal never staffs a loop.** Its role binding gives reach, never occupancy ([ADR-0027](../adr/0027-a-service-principal-acts-through-a-role.md)).

## 2. Identity and entry

### Two acts, two lifetimes

**Sign in** authenticates a principal to the application. It confers no role, no reach and no audio. **Assume** takes up a role and creates the **session** that carries voice. **Relinquish** ends the session and returns the user to the **lobby**. Signing out ends everything ([ADR-0023](../adr/0023-sign-in-is-to-the-application-and-a-role-is-assumed.md)).

A user has **at most one session**, though they may be signed in on several machines. Assuming a role elsewhere ends the previous session and tells it why. Changing role is a relinquish followed by an assume, and the console says so — audio genuinely stops, and dressing that as a smooth transition is the class of lie the product exists to avoid.

### The lobby

Read-only, no audio, no authority. It shows the roles the user is eligible for, who occupies each, and the **staffing state of the loops those roles staff, with the reason** — enough to answer *should I assume a role, and which?* and deliberately nothing more. The reason is carried in full here, ledger-style rather than board-style: the lobby is read once and deliberately, by somebody about to be in a position to fix what it says, and `away — 2 not subscribed` tells them the seat's loops need setting up before they take it. No talking indicators. It renders session **tombstones**, so a returning client learns *why* its session ended rather than merely that it did ([ADR-0041](../adr/0041-a-session-is-resumed-by-name.md)).

### Lifetime

**No idle timeout on a session and no absolute cap on a sign-in.** A sign-in ends after **24 hours with no deliberate act**, and that clock runs only in the lobby — assuming a role stops it. An operator holding `Flight Director` through a thirty-hour incident is not signed out for failing to click anything.

| Event | Occupancy | Sign-in |
|---|---|---|
| Relinquish | ends | survives → lobby |
| Assume elsewhere | previous ends | both survive |
| Eligibility revoked | ends immediately, reason shown | survives → lobby |
| Forced relinquish | ends | survives → lobby |
| Account lock | ends | ends |
| Administrator-forced password reset | ends | ends |
| Enrolment code redeemed | ends | ends |
| 24h with no deliberate act in the lobby | n/a | ends |
| `disconnected` | **survives** for the reconnection window | survives |
| Server restart | ends | survives |

### The identity seam

**The authentication adapter's entire output is a resolved internal user id.** Nothing downstream — lobby, eligibility, grid, session, audit — ever learns how the principal authenticated ([ADR-0024](../adr/0024-identity-is-a-replaceable-front-door.md)).

A user record carries an **immutable opaque internal id** (the only thing anything references), a **mutable username**, and a **nullable external identity** — the (issuer, subject) pair — stored in v1 though nothing writes it yet.

**Email is never an identity key and never a join key.** Linking a VoxLoop user to an external subject is an explicit administrative act. Auto-matching on email would let whoever can set that claim inherit a role carrying `control`.

**The seam carries identity only** — no groups, no claims-to-roles mapping. Permissions stay in the grid.

**A local break-glass administrator is permanent**, surviving SSO adoption. An identity-provider outage locking every administrator out mid-event is worse than the account it protects.

Local passwords are the **first implementation** of the seam, not a bypass around it. The adapter is v1 work even though there is one implementation.

### Credentials, with no mail path

There is no mail path, so every flow that leans on one is unavailable by construction ([ADR-0025](../adr/0025-credentials-are-administered-because-there-is-no-email.md)).

- **No self-registration.** Every user record is created by system administration, starting with seeded `Observer` eligibility.
- **Enrolment codes** replace every link an email would have carried: single-use, expiring, issued by an administrator, handed over out of band. A reset is the same act again. There is **no self-service reset**. Issuing one invalidates whatever that user had outstanding, so a mislaid code is replaced rather than left in circulation, and a code is handed back exactly once — nothing reads one back afterwards, the audit log included. **Redeeming one ends every sign-in the user holds**, because the credential those sign-ins stood against is not the one the account has any more; in the ordinary flow the forced reset has already ended them.
- **A signed-in user may change their own password**, re-presenting the current one. It does not end their session ([ADR-0054](../adr/0054-every-operation-declares-its-authorisation.md)).
- **Argon2id, 12-character floor, no forced rotation, no complexity rules.**
- **No MFA in v1.**
- **Rate-limit, never auto-lock.** Auto-lock is a denial-of-service aimed at whoever is starting a shift. Limits key on **source**, never on the submitted account name, with a global ceiling behind them. Account lock survives as a deliberate administrative act.
- **No default credentials, ever.** On first start with no system administrator, the server mints a one-time **bootstrap code** to its own log, re-minted every start and invalidating the previous one. The route is not registered once an administrator exists.
- **An on-box CLI** can create an administrator and reset a password. It is permanent, not a first-run tool.
- **The last system administrator cannot be removed** — clearing the flag on, locking or deleting the final one is refused.

### Service principals

A **service principal** is a non-human principal holding a long-lived administered token, **bound to a role**. Its reach is that role's row and its attribution is that role. It has no password, no lobby, no session, no subscriptions, no presence and no interactive sign-in, and it **never carries media over the network** ([ADR-0027](../adr/0027-a-service-principal-acts-through-a-role.md), [ADR-0029](../adr/0029-an-announcement-is-an-ordinary-transmission.md)).

Roles bound to a service principal should be modelled as roles no human is eligible for, so *who occupies `Ground Alarms`* has the honest answer *nobody, ever*.

## 3. Authorisation

**Nothing defaults to open.** Every operation carries exactly one of six requirements, supplied as a **mandatory argument at route registration**, so an unruled operation is a build failure rather than an open door ([ADR-0054](../adr/0054-every-operation-declares-its-authorisation.md)). The enumeration is [`api-surface.md`](./api-surface.md); an operation missing from it cannot exist.

| Requirement | |
|---|---|
| `Public` | no principal |
| `SignedIn` | authenticated user, no role |
| `Session` | a role assumed |
| `Grid(rung, loop)` | the **acting principal's** role holds at least `rung` on `loop` — the assumed role for a user, the bound role for a service principal |
| `SystemAdministration` | the user-level flag |
| `ServiceToken` | a service principal |

There is no seventh. `Self` was rejected as a check inside a handler rather than a rung; splitting `SystemAdministration` into read and write was rejected as the beginning of a second grid.

**One operation has a caller and an actor that are different principals.** The admin console's announcement page is `SystemAdministration`, and the `Grid(emit, loop)` check runs against the principal the server acts *as* rather than the administrator who called ([ADR-0066](../adr/0066-the-console-announces-as-the-designated-principal.md)). Two checks, two principals, still one requirement on the row.

**The socket is a second authorised surface, checked per message** — not at upgrade. Cut, forced relinquish and monitoring directives are all socket messages, and a grid edit lands mid-shift. **One socket per tab, opened at sign-in**, starting at `SignedIn` with the lobby document and moving to `Session` on the hello that presents a session id.

**The cookie carries no claims.** Neither the system-administration flag nor the assumed role is in it, which is what makes revocation genuinely immediate: the flag is read from the store and the role from the state authority, per request.

**A request carries exactly one credential kind.** Cookie plus token is refused rather than resolved by precedence. The token rides an `Authorization` header, never a query string, and the socket upgrade refuses tokens outright. The console announcement page does not bend this: it sends a cookie and nothing else, and the server holds no token for the principal it acts as.

**Every authority act names the loop it claims authority through.** Cut, forced takeover and forced relinquish each used to derive their loop differently; now the caller names it, the server checks `control` on it and the target's reachability through it, and the audit entry records it.

**`control` compels. It does not configure, and it does not merely ask.** The rung is for changing another session's live state against their will. Configuration is `SystemAdministration`. A **hail** stays on `emit`, because it is dismissed with one click. Any later proposal to put something on `control` has to show it compels.

An **unreviewed loop**'s cells are enforced as `none`, with no exception. `unreviewed` is a display state and an administrator's prompt; the evaluator cannot tell it from a deliberate `none`.

**A refusal says what the caller did not meet**, rather than hiding an operation's existence — one organisation on one box. The bootstrap route is the sole exception, and it genuinely stops existing. **A credential that was not accepted is not a refusal** and does not answer as one: the caller may perform the operation, and what they presented was wrong — telling somebody holding a mistyped enrolment code that they may not redeem enrolment codes is an answer they cannot act on. **Refused authority acts and refused administration writes are audited; refused reads are not.**

The unauthenticated surface is four things plus one: the static bundle, sign-in, enrolment redemption, bootstrap redemption, and a **liveness route** returning liveness only — no version, no counts, no names.

## 4. Speaking

### Arming and keying

Emission decomposes into two acts with different enforcement ([ADR-0008](../adr/0008-emission-is-armed-by-the-server-and-keyed-by-the-client.md)).

**Arming** selects a loop as a destination. It is **enforced by the server in the media plane** — no fan-out entry exists to a loop the role lacks `emit` on, so there is nothing to bypass. Arming and disarming are pure routing changes: instant, with no renegotiation.

**Keying** actually transmits on the armed loops. It is performed **by the client** for latency and **signalled** to the server, which remains the sole authority for telling anyone else it is happening. An operator's own transmitting lamp is lit by the server's acknowledgement, never by their own button going down, and the console must not pre-light it.

**Arming is independent of subscription** ([ADR-0013](../adr/0013-arming-is-independent-of-subscription.md)). You may emit to a loop you do not monitor, and monitor a loop you are not armed on. Nothing but a subscription puts a loop in your ears — because staffing state is read off subscriptions, and arms pushed into that set would make loops read `staffed` because somebody was *talking at* them.

**Emitting blind is therefore legal**, and compensated in the console: every armed loop shows whether someone is currently transmitting on it, and **blind-armed loops are named in words**, not just coloured.

**Revoking `emit` mid-transmission cuts it instantly** — mid-word if necessary — tells the talker why, and tells the loop that a transmission was **cut** rather than ended. A voice vanishing mid-word is otherwise indistinguishable from a fault.

The residual is stated rather than implied: a compromised or defective client can keep sending while claiming to be unkeyed. The arm boundary caps it to loops the role may already reach, and mediasoup's `AudioLevelObserver` — which **runs in v1**, not as optional instrumentation — makes the discrepancy detectable server-side.

### Emission modes and input

Two modes and no third: **momentary** (held) and **latched** (press to open, press to close). Latched subsumes "open mic".

**Every push-to-talk input source publishes a level and a liveness flag, never events** ([ADR-0021](../adr/0021-ptt-input-is-a-level-with-liveness.md)). The client ORs the live sources. Edges are lossy and their loss mode is an open mic; a level is self-correcting. Liveness is what expresses *the headset was unplugged while you were holding it* — a property of the source, not of any event it could have sent. A source that dies while keyed forces an unkey and says so locally. **The microphone and the PTT source are independent liveness signals.**

A source reports intent; **it never knows which emission mode it serves.** Mode logic lives above the seam.

**Latch always has its own binding** and is never derived from a momentary press — no short tap, no double tap, no held duration ([ADR-0022](../adr/0022-latch-is-never-derived-from-a-momentary-press.md)). Deriving it would make an open mic the failure mode of a hardware fault. **A single-button device is therefore momentary-only.**

Three bindings, all user-configurable:

| | Default | |
|---|---|---|
| Momentary | `` ` `` | |
| Latch | `` Shift+` `` | |
| Priority | ``Ctrl+` `` | momentary only; **priority never latches** |

Space is rejected (activates focused controls, scrolls, types) and `CapsLock` is rejected (unreliable `keyup` on macOS — an unreliable release on a PTT key is an open mic). **PTT keys are live only under an assumed role, and never while focus is in a text field or on an interactive control**; the console must not place a focusable control where an operator's hands rest.

**Keystroke footswitches are supported for free** — they are just keyboards. They are the only PTT peripheral v1 supports, and VoxLoop ships none.

### Presets

A **preset** momentarily replaces the armed set while keyed, reverting on unkey ([ADR-0013](../adr/0013-arming-is-independent-of-subscription.md)). It serves two symmetric needs: reaching every loop for an announcement, and narrowing to one group for a single question.

- **Named "preset", not "broadcast"** — it narrows as often as it widens.
- **Reach is the grid and only the grid.** A preset silently narrows to loops the role may emit on, showing the excluded ones greyed. A role that must reach everything is *given* `emit` on everything, where the grid shows it.
- **Exclusive, not additive.** While keyed, the preset's set *is* the destination.
- **Momentary only.** Latched presets are refused outright.
- **Role presets and personal presets both exist**, rendered distinctly. Role presets are system administration; personal presets are personalisation, scoped to (user, role). *(See [§17](#17-what-assembly-found-and-how-each-was-closed) — role presets were settled in ADR-0013 and then omitted from every later enumeration.)*
- Presets live **on the transmit bar**, not among the loop cards.

### Priority

**A priority transmission plays at full gain in every subscriber's ears whatever they set that loop's volume to. That is the whole of interruptive priority in v1** ([ADR-0045](../adr/0045-priority-defeats-attenuation-and-nothing-else.md)).

It **lowers no other talker, defeats no mute, and compels no subscription.**

**Nothing in VoxLoop ever ducks.** Ducking is rejected outright: the console structurally cannot say *who* caused your audio to drop, it makes audio the operator asked for get quieter, and "who gets ducked" is an authority question the grid cannot express.

The gap priority is scoped to is precise. Mute is surfaced twice over — a loop drops to `away`, and the transmit bar counts `present, not hearing`. **Per-loop volume is the one attenuation in VoxLoop that nothing warns anybody about.**

Priority is **an act, not an attribute** ([ADR-0046](../adr/0046-priority-is-keyed-not-held.md)). Not a loop flag, not a grid bit, not a property of a person or a role. It is conferred by holding the third momentary binding, and it lasts exactly as long as the key.

- **Available to anyone holding `emit`.** The specialist spots the anomaly, not the lead. Gating on `control` would also break announcements outright, since it would mean handing the synthesis service the authority to cut people.
- **Audited on every press, with no minimum duration** — actor, role, armed loop set, timestamp, duration. Abuse may look like a hundred short presses, so filtering belongs to the reader.
- **The level model absorbs it with no special case**: `emitting = ordinary-level OR priority-level`, `is-priority = priority-level`. Pressing priority while latched elevates without touching the latch; pressing it from cold both keys and elevates.
- **Priority applies to the whole arm set.** One stream, server-side fan-out — you cannot be priority on one armed loop and ordinary on another. A wide arm set overrides volume on many loops at once. That is the abuse vector, ungated by choice.
- **Priority bypasses loudest-wins** rather than competing with it.
- **Cut beats priority**, so the existing escalation still works against abuse.
- There is **no personal opt-out** — that would make the feature nothing, and mute is already the escape.

**A priority transmission is marked wherever it lands** ([ADR-0059](../adr/0059-a-priority-transmission-is-marked-wherever-it-lands.md)) — on every loop it reaches, on the console of everyone monitoring it, at full volume and on a muted loop. The mark is a **declaration that somebody called this urgent**, not an explanation of why the gain changed. It names nobody. It has **no minimum display time**, so a sub-second press can leave no trace on any console; the audit log is then the only record.

### Cut, takeover and relinquish

Nothing an operational authority holder does during an event changes the grid. What exists instead are transient acts ([ADR-0014](../adr/0014-authority-acts-on-emission-are-transient.md)).

**Cut** stops a user's emission, **latched until cleared**. It applies to the **whole uplink**, not one loop — a user emits one stream and an open mic is open on all of them. It is enforced server-side by closing the fan-out, so it works whether the target's client is cooperative, stale or hostile. **The target clears it themselves**, as may any `control` holder. It dies with the session. It is latched rather than one-shot because of the stuck footswitch, and it exists to **announce** an open mic, not to punish one.

Cut reaches a conversation on a loop the cutter holds nothing on — whole uplink, plus a caller-named authority loop ([ADR-0055](../adr/0055-there-is-no-conference-loop.md)). They cannot hear it; they can end its audio.

**Forced takeover** of a single-occupant role, and **forced relinquish**, are gated on `control` on a caller-named authority loop the target's role staffs. Forced relinquish has a loud side effect — the role goes vacant and every loop it staffs changes staffing state — so the console must make it obvious before the act.

**Assuming an occupied single-occupant role is always refused**, never granted silently. An eligible user sends a **takeover request** to the incumbent; it happens by consent or by operational authority.

**Force sign-out and account lock are two capabilities**, falling on opposite sides of the role/user split. Ending a session is operational; disabling an account is system administration.

### Audio and latency

Opus, **48 kHz, mono, 20 ms frames**, ceiling around 32 kbps, **inband FEC and DTX both on** ([ADR-0010](../adr/0010-opus-mono-and-the-latency-budget.md)). Mono because panning is a presentation choice the console makes over mono sources, for free.

| | Target |
|---|---|
| Mouth-to-ear, LAN | ≤ 150 ms |
| Mouth-to-ear, VPN | ≤ 300 ms |
| Fault threshold — the operator is **told** | > 400 ms |
| Key to first audio | **< 100 ms** |

Key-to-first-audio is what makes this feel like a radio rather than a conference call, and it is what client-side keying buys.

**Stated honestly: VoxLoop will be measurably laggier than the hardware it replaces** — 80–150 ms realistically, against 30–60 ms for professional IP intercom and effectively instant for circuit-switched loops. Say this to the pilot rather than let them discover it. These are targets to be measured on the pilot's actual network, including a VPN client, before v1 is called done.

## 5. Listening

### Subscription, mute and volume

**Subscription** is the live choice to monitor a loop, held per session. Distinct from permission: permission says which loops a role *may* monitor, subscription says which it *currently is*. The set is remembered as personalisation, so assuming a role restores the loops that role last had.

**Mute** silences a loop in the user's own ears and affects nobody else. It is a personalisation, not a permission and not an unsubscribe — the subscription stands, so loop health, talking indicators and priority marks keep arriving. Muting a loop you staff **contributes to** it going `away` but does not decide it. **A mute is never remembered**, because a forgotten one silences a loop the moment its owner assumes the role again. A mute does not auto-expire — an unexpected un-mute mid-incident is its own hazard.

**Per-loop volume** is personalisation, scoped per (user, role, loop), behind a cog on the card and the row. Every loop starts at unity. It is not a live operational control and must not be nudgeable from the main surface.

**Loudest-wins.** When a talker emits to several loops a subscriber monitors, the loudest applicable loop volume wins. Volume is an attenuation control, so a transmission also going to a loop the operator kept up is one they have already signalled they want to hear. Quietest-wins would let a suppressed loop silence a transmission they care about.

### Monitoring directives

A **monitoring directive** puts named loops on the consoles of everyone occupying named roles, marked as directed and carrying the reason ([ADR-0035](../adr/0035-a-monitoring-directive-promotes-a-loop-it-does-not-police-it.md)). From that moment the subscription is an **ordinary** one: droppable, mutable, reorderable.

- **Gated on `control`** on every loop named.
- **Additive only.** The exclusive form — where the directed set replaces an operator's subscriptions — stays rejected, because it could silently drop the one loop where the real problem was unfolding.
- **Applies once per session**: when issued, and again to anyone assuming a targeted role while it stands. Dismissal is session-scoped.
- **Stands until cleared.** No auto-expiry.
- It **cannot outrank the grid** — a role that loses `monitor` on a directed loop stops receiving it.
- **The issuer is not told it was dismissed.** The feedback already exists where it is actionable: the transmit bar's audience count, read a moment before keying.

**Enforcement was retired.** The certainty it bought is unavailable at any price — an operator who cannot drop a loop can still mute it, zero it, or walk away, and the directive reports success in all three cases. **Nothing in VoxLoop now makes a subscription undroppable**, and nothing can compel one to be kept.

### Hails

A **hail** is the monitoring directive with the authority taken out of it ([ADR-0047](../adr/0047-a-hail-is-a-monitoring-directive-without-the-authority.md)). Anyone holding `emit` on a loop may hail a role — or one named person occupying it — to that loop. It lands as a marked, droppable **directed subscription** plus a banner saying who asked.

| | Monitoring directive | Hail |
|---|---|---|
| Who may | `control` on the loop | `emit` on the loop |
| Lifetime | stands until cleared | one-shot |
| Reaches | whoever holds the seat, now or later | whoever holds the seat at that moment |
| Audited | yes | **no** |

The gate is `emit` rather than `monitor` because a hail means *come hear me*. It is unaudited because it grants nothing, changes no configuration, and is shed with one click.

- **A hail reaches a seat, not a person.** There is deliberately no reasoning about other roles a target is eligible for, and no way to hail someone into a different seat. A user in the lobby is not hailable.
- **No sound, no modal, no focus steal.** Anything louder would make a colleague's request more intrusive than a priority transmission.
- **No reply channel** — no *on my way*, no *busy*. A reply would be VoxLoop's first person-to-person message.
- **Repeat hails coalesce per (hailer, target)**, which is the entire rate limit.
- **A hail to a `disconnected` session lands on resume** as a gap event, carrying its age. Past the reconnection window the seat is empty and there is nothing to deliver to.
- If the target already subscribes, the hail is purely the sentence.

## 6. State

### Provenance

**Observed state** the server has seen for itself. **Asserted state** is a claim a user made about themselves, of which there is exactly one: **off console**. Asserted state is only as true as the moment it was asserted, so it is always shown alongside **how long ago the claimant last did anything deliberate**, and it is never rendered like observed state ([ADR-0016](../adr/0016-displayed-state-is-observed-or-asserted.md)).

**VoxLoop never guesses whether a human is in the chair.** Idle-based auto-away is rejected — an operator watching telemetry is idle at the keyboard and very much on console. **Off console is cleared by any deliberate act** — keying, changing a subscription or an arm, answering a prompt, dismissing a banner — and never by mouse movement, scroll or focus. Declaring off console drops the staffing state of the loops you staff to `away` and **changes nothing else**: subscriptions stand and audio keeps flowing.

**A stale assertion is still shown, with its age.** VoxLoop makes the ambiguity visible and leaves the judgement with the human. This is a deliberate refusal to be helpful.

### The presence document

State is **one versioned document per session, pushed by the server and rendered atomically** ([ADR-0019](../adr/0019-presence-is-one-versioned-document-scoped-to-reach.md)). Independent per-topic streams were rejected: they permit a **torn state** — arms as of one instant beside subscriptions as of another, each individually true, the combination never true at any moment. A lie assembled entirely from facts.

**Versions are monotonic per session and survive reconnection.** The document is **scoped to reach** — a session receives presence only for loops its role holds at least `monitor` on. One gate or none: leaking the state of loops a role cannot touch would erect a second, softer boundary beside the grid that nobody configured.

**The document is the API.** Whatever the console renders must be in it, and anything in it is something the server has committed to keeping true. It carries, per loop, **whether this session's role staffs it** — §8's mark is derived from that field and the session's own subscription set, not inferred.

Wire format: full document, JSON, ~5 Hz tick, `permessage-deflate` **with context takeover** — consecutive documents are near-identical, so carried context *is* a delta encoding, and resynchronisation stays one message. The WebSocket carries only live state and signalling; everything configuring the system is HTTP.

**Occupancy is not scoped to reach; loop state is** ([ADR-0048](../adr/0048-the-hail-picker-is-the-only-place-the-console-names-a-person.md)). A roster leaks no loops and no authority, and who is on shift is the least secret thing in a control room. The hail picker's occupancy is a **snapshot fetched on open**, deliberately not part of the presence document.

### Audience

The **audience** is who would actually hear a given emission, resolved per (role, user) into three buckets: **hearing**, **present but not hearing** (muted, off console, unreachable, or not receiving the beacon), and **not subscribed**. It is **computed, not stored**, and it is shown **before** keying, not only during.

The three-way split is the point: a subscriber list that silently includes people who cannot hear you answers *who chose to listen* when the operator asked *who will hear me*.

This makes one person's mute visible to their colleagues. Accepted deliberately, and mitigated by presentation rather than concealment — privacy of that kind is not on offer in a single-organisation operations centre whose defining requirement is certainty about who hears you.

### Three independent axes

Any console state must be read against all three. They fail independently, in both directions, and each says something the others do not.

**Connection state** — the session's standing with the signalling channel ([ADR-0018](../adr/0018-no-signalling-channel-means-no-emission-path.md)):

| | | |
|---|---|---|
| `confirmed` | heartbeats current | everything normal |
| `unconfirmed` | heartbeats missed (5s) | displayed state frozen and marked stale with a running age; **PTT still live** |
| `disconnected` | past the threshold (12s) | PTT disabled, server closes the fan-out, banner. Loops the session staffs drop to `away` — *unreachable*, with the age |

**A session with no signalling channel has no emission path.** Every talking indicator anyone sees is a server broadcast, so an operator keying with no channel transmits into a system where nobody's console will show them, no loop attributes it, and no authority holder can cut it. The audio arrives; the accountability does not. The client disables PTT **and the server closes the fan-out** — the client-side half alone would be a courtesy, in exactly the situation where the client may be wedged.

In flight: **a momentary key survives to release** (or to `disconnected`), because a held button is a human continuously asserting intent. **A latched emission is dropped after ~2s of `unconfirmed`**, because a latch's entire safety story is that the console will show it to you, and that story is void the moment the console cannot be trusted. This is **the one place VoxLoop cuts audio it cannot announce**, and the client announces it locally — the only user-facing message in the product that does not originate at the server.

**Media path state** — the session's standing with the audio transport ([ADR-0042](../adr/0042-the-media-path-has-its-own-ladder.md)): `connected`, `impaired` (a transient fault that routinely self-heals), `lost` (emission withdrawn). **A session with no media path has no emission path** either — the mirror case, where a healthy console shows an armed, keyable operator whose voice reaches nobody.

It is **client-driven**, because mediasoup's server-side `iceState` has no `failed` and takes ~30 seconds of ICE consent freshness to declare loss — longer than the whole signalling ladder. The browser's `disconnected` maps to `impaired` and `failed` to `lost`; mediasoup's `on_ice_state_change` is the **backstop** for the wedged or lying client. Both ends merge pessimistically: **green needs both, red needs one.**

Unlike a signalling loss, this failure **is announceable**, so the operator is told exactly what is wrong and the loop is told a transmission was *cut*. **The transmit bar must say which** of the two withdrawal conditions applies — they are different problems with different fixes.

**Loop health** — whether a session is actually receiving a loop, per (session, loop) ([ADR-0017](../adr/0017-loop-health-is-measured-not-asserted.md)). Two subscribers may correctly disagree.

DTX means silence sends no packets, so a quiet loop and an unreachable loop are indistinguishable both to packet-watching and to the ear. **They must never look identical.** So each loop carries a **loop beacon** — a silent low-rate stream, always on, consumed by every subscriber and counted by the client, reported over the signalling channel. It is an end-to-end measurement over the same transport, router and fan-out that speech traverses, at roughly 240 packets per second across the whole pilot deployment.

The beacon **must be excluded from the recording tap and from `AudioLevelObserver`**, or it registers as a permanent talker on every loop and a permanent signal in every recording. **A loop with no subscribers still runs its beacon.**

The client also **watches its own output path** — a confirmed check tone at assume, `devicechange` monitoring thereafter, and detection of a default-device swap by comparing the label and group of the `default` entry across change events. The likeliest real *"I can't hear Flight"* is an unplugged headset or Windows silently repointing the output.

**Beacon loss drops the loop to `away`**, which is what upgrades staffing from *says they're listening* to *demonstrably hearing*, and fails safe for a wedged client. **Beacon loss is suppressed while connection state already explains the silence**, or one failure arrives as two competing reasons.

**Recorded and not closed: beacon arrival does not prove you would hear a given talker.** The downlink is per talker, so the beacon's consumer is a different consumer from the one carrying anyone's voice. Beacon *loss* soundly proves deafness; the converse does not hold. A beacon per (loop, talker) would close it and was rejected as forty times the mechanism.

## 7. Reconnection

**A session is resumed by name.** `assume` mints a **session id**, which the client keeps in the tab's `sessionStorage` and presents on the WebSocket hello ([ADR-0041](../adr/0041-a-session-is-resumed-by-name.md)). The cookie names the *user*; reattaching on it alone would let a second tab or a phone silently steal the live console's socket.

The session id is **not a credential** — it is presented over a channel the cookie already authenticated and can only select among that user's own sessions.

**Reattachment is exclusive.** A successful reattach evicts any socket already holding that session, telling it why. **The retry policy keys on why the socket closed**, not on the fact that it closed: a transport failure auto-reconnects, a server-sent eviction is terminal and the tab sits in a local end state until a human acts. Without this, `Duplicate Tab` — which copies `sessionStorage` — makes two tabs evict each other indefinitely.

| | |
|---|---|
| heartbeat | 2s |
| `unconfirmed` | 5s |
| latched emission dropped | 2s of `unconfirmed` |
| `disconnected` | 12s |
| reconnection window | 120s |

All four are **startup settings with a hard ceiling** — the disconnect threshold is a safety parameter that must be tuned against the pilot's VPN, but an unbounded knob lets a site set it to five minutes and reintroduce exactly the hot mic the rule removed.

**Expiry is a relinquish**: loops drop, the role frees, an audit entry records the reason, and the user is left signed in, in the lobby, told why. **It never auto-assumes.** A reaped session's loops go `away` → `vacant` at the 120s mark, which is the moment a colleague learns the position is genuinely free.

**A blip must never read `vacant`.** Occupancy survives, so loops drop to `away` at `disconnected`, not at `unconfirmed` — `unconfirmed` means precisely *we cannot confirm*, which is not yet a fact about staffing.

**An unrecognised session id is explained, not merely refused.** Session **tombstones** (id, end reason, timestamp, ~15 minute memory) cover reaped, assumed-elsewhere and forcibly-ended. The hello carries the **server's instance id and start time**, which covers the one case a tombstone structurally cannot: after a restart every session id is unknown, and a client comparing instance ids reports *the server restarted* rather than implying this operator timed out.

### What a resume restores

**Everything server-held returns unconditionally** — occupancy, subscriptions, mutes, arms, the off-console assertion — with no reconfirmation and no ceremony ([ADR-0043](../adr/0043-a-resume-restores-everything-except-the-key.md)). The client has no local model to reconcile; the projection simply resumes. A graduated restore was designed and dropped: an arm can only change by the operator's own hand or by a revocation that removes it server-side, so a restored arm set is exactly what they chose.

**Key state never returns. A resumed session is always unkeyed.**

**A key still held across the outage is suppressed until released.** PTT input is a level, so an operator still holding the button presents HIGH and audio would begin the instant the predicate is satisfied — a hot mic with a randomly-timed start, at a moment they cannot know. **A source that was HIGH across a PTT withdrawal is marked stale-high and contributes nothing to the OR until it transitions LOW then HIGH again.** One rule covers both ends of the outage.

**A resume is the network's act, not the human's.** The off-console assertion stands untouched and a reconnect does **not** refresh last-active.

### Recovery order

Fixed by the API, not chosen: `restart_ice()` returns fresh `IceParameters` that must be signalled, so an ICE restart is impossible without a working signalling channel.

1. Signalling channel back to `confirmed`.
2. `restart_ice()` and re-signal — keeps the transport, producer and every consumer alive. The cheap path.
3. Full transport rebuild, only if that fails.

A rebuild needs the producer, a beacon consumer per subscribed loop, and consumers for whoever is currently talking. Order is **producer, then beacons, then talker consumers**, and **PTT waits only on the producer**. The full predicate for re-enabling emission:

> the presence document has arrived **and** the producer is created and server-confirmed.

Beacons are deliberately excluded — waiting on twenty loops' health before the loudest voice in the room can speak buys no safety.

**A page reload is a resume with a media rebuild**, so the rebuild path is exercised constantly rather than only in failures.

### Gap events

Current state cannot express a change to state: a dropped latch is indistinguishable from one never set. So **the first document after a resume carries a bounded set of gap events** — things done *to* the operator while they were dark ([ADR-0044](../adr/0044-resynchronisation-narrates-the-gap.md)):

- a latched emission was dropped
- the operator was **cut** by operational authority
- permissions changed underneath them, removing arms or subscriptions
- a **monitoring directive** added loops
- the role was force-relinquished
- a colleague **hailed** them

**Never a diff.** The presence document is a projection the state authority computes rather than a record it keeps, so there is no history to diff against, and a diff would bury the six things that matter under everything that merely moved. The server always sends a full document.

They render as a **dismissible banner in both console views**, in the same slot as the stale-state banner, **persisting until dismissed** — a dropped latch that faded out unread is the failure this exists to prevent. **Repeated gaps coalesce rather than stack.** A dismissal is a deliberate act, so it refreshes last-active — unlike the reconnect that produced it.

The banner slot is the console's general channel for **things you were told**: a **hail** lands there while the session is perfectly healthy.

## 8. The operator console

**Two views of one loop list**, both complete, both driven by the same presence document, so they cannot disagree about anything except layout ([ADR-0032](../adr/0032-the-console-is-two-views-of-one-loop-list.md)).

**The board** — a card per loop in reach. The glanceable view; the operator wants the classical board and it is what a control room reads at a glance. **The ledger** — a compact table row per loop. The reading view, and where state too long for a card lives.

**Order is shared** — reordering in one reorders the other. Two independent orders would put the same loop third in one view and eleventh in the other, which is the quiet kind of disagreement that teaches an operator to distrust the console.

**Every state added from here costs twice, and a state that renders in only one view is a bug.**

### The card

- **Clicking the body toggles monitoring**, with no confirmation. Optimistic rendering is banned so the click visibly lags, and a misclick on a loop you staff announces itself by dropping it to `away` for everyone.
- **Arm, mute and cog controls must not propagate that click.**
- **The loops this role staffs are marked** in both views, in **two states** ([ADR-0065](../adr/0065-the-staffing-flag-reports-it-never-subscribes.md)) — *you staff this*, and *you would staff this and are not subscribed*. The safety argument above depends on the operator knowing which loops they answer for, and staffing is per (role, loop) so it cannot be inferred. The second state is the actionable one, and clicking the card body is the whole fix. Showing the mark **only** in the second state is rejected: it would make the mark an alarm rather than a fact about the operator's own console, and appear for the first time at the moment something is wrong.
- **Staffing state is a word on the board and a sentence in the ledger** — `away — muted it`, `away — off console`, `away — not subscribed to it`, `away — not receiving it`. Blank where the loop has no staffing roles.
- **Where occupants are away for different reasons the ledger counts them** — `away — 1 muted, 2 not subscribed` — collapsing to the plain sentence when they agree. No single reason wins by precedence, because none is defensibly ahead of another: a mute is one click from hearing and so is a subscription. Within **one** occupant the reason reported is the one furthest upstream, in the order `unreachable`, `off console`, `not subscribed`, `not receiving it`, `muted` — each still true if everything below it were fixed. This generalises §7's existing suppression of beacon loss under connection state.
- **No banner announces an unsubscribed staffed loop.** Designed and dropped: it would be the first server-generated advisory in the product, needing a slot, a lifetime and a dismissal rule, to say what the card already shows.
- **Blind-armed loops say so in words**, not just a border.
- **Per-loop volume is behind a cog**, opening a modal scoped to that loop and holding only volume in v1.
- **A loop entering reach is appended at the end and marked new** until the operator moves it or dismisses the mark. This is where unreviewed loops ruled on months after install surface to operators, and the marking is the whole of the notification.

### The talking indicator

**The console shows that a loop is being spoken on, and never who** ([ADR-0033](../adr/0033-the-console-shows-that-someone-is-talking-never-who.md)). A single indicator on the loop, identical for every talker and any number of them. A loop is staffed by people who can speak for it, so *the loop is the identity*, and asking which occupant is talking asks the question the loop exists to make unnecessary.

**It may animate, and may never imply amplitude.** DTX means silence sends no packets, so a level meter would be inventing a signal. One fixed rate, one fixed shape, reading unambiguously as on or off. Motion is permitted here and nowhere else.

**It has exactly one variant, and it is not attribution**: the priority mark.

**Announcements are marked explicitly** — a flag in the presence document, not derived from *roles no human is eligible for*, because derivation by convention quietly breaks.

**Attribution leaves the screen.** It is still carried by the model and read by recording, but v1 ships no surface where an operator reads who is talking. Anything later wanting *who said that* starts from the model.

### The transmit bar

Present in both views, positioned differently, **worded identically**, and **never scrolled away** ([ADR-0034](../adr/0034-the-transmit-bar-is-always-visible-and-the-audience-is-a-count.md)). It carries the armed set in words, the audience as two counts, and the key state.

**It stays live while keyed** ([ADR-0058](../adr/0058-the-transmit-bar-is-live-while-keyed.md)), so it answers both *who am I about to talk to* and *who am I talking to* with the same words. With the receiver told nothing about a transmission's other destinations, **this is the whole of VoxLoop's compensation for multi-destination emission.**

- **The audience is counts, not names** — `6 hearing`, `1 present, not hearing`. Sixteen names is more than anyone reads in the second before keying, and the two numbers that remain are the two that change a decision: the first is reassurance, the second is a warning. The third bucket — people in reach who did not subscribe — is computed and **not shown**, because it is not actionable.
- **`present, not hearing` is the console's only warning about mute**, and it is the compensating signal for several gaps: mute defeating an announcement, mute defeating a directive, mute defeating a hail.
- **A zero audience never blocks a transmission.** `0 hearing` renders in the warning colour and the operator keys anyway if they mean to. Blocking it, or interposing a dialog, would be the console overruling an operator about their own operation.
- **Only a change the session did not ask for is marked.** A preset is a mid-key change by design and the most routine one in the system; marking it would train the operator straight past the signal. What gets marked is a change the operator's own hand did not make — an administrator pulling an `emit` cell mid-transmission. Provenance costs one flag on the update.
- **At zero armed the latch stands.** A revocation can empty the arm set outright, leaving somebody keyed with nothing routing. Releasing the latch for them is the obvious fix and it is wrong: taking the key out of somebody's hand mid-sentence is a bigger lie than showing them an empty arm set. **The key control renders differently at zero armed instead.**
- **No third audience count.** The bar could say *3 of 6 have this turned down* and does not: it would be read as another flavour of `present, not hearing`, and volume is persisted precisely because it is safe to be stale, so it can be wrong.
- **Presets live here**, beside the key control.
- **A hot latch is announced by a persistent banner with a running age**, plus the key control rendering live in both views.

### The hail picker

Opened from a loop, listing the **roles permitted to hear that loop**, each expanding to whoever occupies it — so one control hails a role or a person at two levels of one list ([ADR-0048](../adr/0048-the-hail-picker-is-the-only-place-the-console-names-a-person.md)).

**It is the only place the console names a person, and it names them as the holder of a seat** — never as the source of a transmission. It survives the counts-not-names rule by that rule's own logic: the third bucket is hidden because it is not actionable, and **hailing is what makes it actionable**.

- **Opens filtered** to what can be hailed; a toggle reveals everyone else **greyed, each saying why in a few words** — otherwise a person missing from the picker is indistinguishable from a person not on shift.
- **Off console and `disconnected` are shown against a person, marked.**
- **A person appears at most once**, because a user occupies exactly one role at a time.
- **It is a snapshot fetched on open.** A seat vacated between fetch and click takes a hail that reaches nobody, silently.

## 9. The admin console

**Reachable from the lobby and from within a session**, gated on the user's system-administration flag and **never on a role** — an operator who is also a sysadmin must not have to drop off the air to add a loop.

**The console reads one row at a time** ([ADR-0015](../adr/0015-the-admin-console-reads-one-row-at-a-time.md)). The primary surface is a **role page** — the row — or a **loop page** — the column — read as a list at full size. A realistic pilot grid fills 167 of 300 cells, so a column read is eleven roles rather than three, and past ~26–30 loops the row header and the far column cannot share a screen.

**The model is untouched by this.** A permission is still one cell with no second layer; a role page *is* the row read and a loop page *is* the column read. **The matrix survives as a secondary reference view** — the only place a whole-configuration read is possible, which is a reviewing act rather than an administering one.

**Eligibility is not a second matrix.** Rendered as one, 190 × 15 was the least legible object built. It is administered from the role (*who may assume this*) and from the user (*which roles may this person assume*).

**Occupancy is admin console state; keying is not.** The console shows who has assumed which role. It does not show who is transmitting — that is operational and belongs to the operator console.

**Every cell edit computes its blast radius and shows it before committing** — who is cut mid-word, whose subscriptions drop, which loop loses its last staffing role, which occupants lose operational authority. This is a **v1 server requirement, not console polish**: it is the compensation for trimming live transmitting state out of the admin console, and it is the only place the grid's stated consequences become visible to the person causing them.

**A loop created after install is `unreviewed`** until an administrator has set or explicitly dismissed each role's cell. Absent-because-denied and absent-because-nobody-ruled render identically otherwise, and `Observer` is seeded only against loops present at install — two silent holes at pilot scale, twenty-two at forty loops. **Auto-seeding `Observer` on new loops is rejected**: it would silently grant reach on every loop created, including the ones created precisely because something should not be broadly audible.

`unreviewed` is cleared **per loop, not per cell**, and it is a display state only — the evaluator enforces `none`.

**Announcements from the console**: an administrator can type text, pick loops and send. It acts as a **designated service principal with its own bound role** — never as the administrator, who has no reach and no attribution. An administrator therefore **cannot announce onto a loop the console's bound role lacks `emit` on**: they must edit the grid first, deliberately, visibly and audited.

The operation is `SystemAdministration`, and **the server executes it as the console principal** ([ADR-0066](../adr/0066-the-console-announces-as-the-designated-principal.md)). No token reaches a browser, so the request carries a cookie and nothing else and [ADR-0054](../adr/0054-every-operation-declares-its-authorisation.md)'s cookie-plus-token refusal is never tested. One call, two checks, two principals: the **caller** holds the system-administration flag, the **actor** holds `emit` on every loop named. It is a second row in [`api-surface.md`](./api-surface.md) and the same implementation as the token path, differing only in how the acting principal is resolved.

**The page may set the priority flag**, and the whole call produces **one audit entry** naming the acting administrator, the bound role, the loops, the flag, the timestamp, the duration and **the text** ([ADR-0067](../adr/0067-composed-text-is-a-decision.md)). A script's announcement stays unaudited: its decision was the token grant, and this path has no per-use grant.

**Install seeds the principal and its role with no reach at all.** The role is not human-eligible, every cell is `none`, and no token is issued — so **the page is inert on a fresh install** and must say so and point at the role's grid row rather than showing an empty loop picker. The seeded role is named `Announcements`, because [the name is spoken aloud](#11-announcements); a site renames it with an ordinary role edit.

## 10. Personalisation

**The role is the profile. There is nothing to switch between** ([ADR-0049](../adr/0049-the-role-is-the-profile.md)). One implicit personalisation set per **(user, role)**, saved continuously, never named. Changing what you are doing means assuming a different role, and `Relinquish` is deliberately a full stop.

**"Profile" is retired from the vocabulary.**

### Scoping

Each item is scoped to the **smallest thing it is actually about** ([ADR-0051](../adr/0051-personalisation-is-scoped-to-the-smallest-thing-it-is-about.md)):

| Scope | Items |
|---|---|
| Per user | PTT bindings — muscle memory follows the person, not the seat |
| Per (user, role) | subscription set, loop order, default console view, personal presets |
| Per (user, role, loop) | volume |
| **Per machine** | audio input and output device |

**The device belongs to the desk.** A headset belongs to a console, not a person — an operator at a spare desk inheriting device identifiers from their own gets no microphone. So **device selection is held client side, in the browser, and never reaches the server.** VoxLoop has no machine concept and inventing one to hang a device identifier off is a large addition for a small return. Accepted costs: no backup, no administrator visibility, no portability between browsers, lost when site data is cleared, and **a device support request cannot be answered from the server**.

### Persistence

**The test is whether a stale value harms the operator before they look at it** ([ADR-0050](../adr/0050-personalisation-persists-what-is-safe-to-be-stale.md)).

| Persists | Does not |
|---|---|
| subscription set, per-loop volume, loop order, default view, personal presets, PTT bindings | **mute**, **arm set**, **off console** |

A stale arm set means keying to a loop you forgot you were armed on, and emitting blind is legal. A stale mute drops every loop you staff to `away` for the whole operations centre the moment you assume, before you have looked at anything. A day-old off-console assertion is not a fact about anything.

**Persisting subscriptions is what makes a restart survivable.** A restart ends every session and every operator must assume again; if subscriptions persist, assuming rebuilds their console instead of every operator rebuilding their loop set by hand during whatever incident caused the restart.

**Personalisation is written through as the state authority applies the live act** — best effort, and it **must never be able to fail a live act**. If the write fails, the console is correct and the preference is lost; refusing a subscription because SQLite is unhappy is the worst available ordering. There is consequently **no personalisation configuration endpoint**: the WebSocket still carries no configuration API, and the endpoint list stays enumerable.

**The grid overrules personalisation silently and always.** It may only ever narrow within reach, it is evaluated against the grid on every load, and it is **kept but inert** when it falls outside — so a temporary revocation does not permanently destroy someone's console arrangement, and a loop that leaves reach and returns comes back where it was.

**Personalisation is not a second authority layer.** It grants nothing.

### Role defaults

A **role default** is the console an administrator sets for a role: **subscription set, default view and loop order**. A (user, role) pair with nothing saved starts from it. It is **applied once and never re-imposed** ([ADR-0052](../adr/0052-a-role-default-is-a-starting-point-never-a-floor.md)), and it is the **only** thing that seeds a console — the staffing flag adds nothing to it ([ADR-0065](../adr/0065-the-staffing-flag-reports-it-never-subscribes.md)). Marking a staffing role and editing that role's default are two independent administration acts, and nothing couples them.

**Volumes are deliberately excluded** — an administrator setting a level for everyone is guessing at headsets and hearing. Every loop starts at unity.

**No enforced minimums.** Subscriptions a role always gets that the user may not remove are rejected on the generalised finding that compulsion is unavailable at any price — and an enforced minimum buys it *worse*, since it would sit behind ordinary role configuration rather than a `control` gate. The honest name for what an administrator wants is *the role's default console*, not *the loops this role must hear*.

**`Observer` ships subscribed to nothing.** Defaulting it to every loop delivers a wall of audio to whoever is least equipped for it, and the board makes silence legible rather than mysterious — an Observer with no subscriptions still sees every loop they could hear and picks.

**Reset to role default** is the single wholesale act, and it always goes to the default **as it stands now** — snapshotting at first assume was rejected because an administrator fixing a bad default would find users resetting straight back into it. It clears the (user, role) and (user, role, loop) items; it leaves bindings and audio device alone, and it **touches nothing live**. It is **confirmed before it runs**, not for safety but because twenty cards redrawing without optimistic rendering reads as a fault unless the operator asked for it a moment earlier.

**No administrator may see or reset another user's personalisation.** The reset button is the support answer to *my console looks wrong*.

**Loop order** is a **complete ordering** of the loops in reach over an administered deployment-wide base order, not sparse pinning over it ([ADR-0053](../adr/0053-the-loop-order-is-complete-and-a-new-loop-lands-at-the-end.md)). Sparse pinning discards every decision that happens to agree with the base order, so the arrangement silently rearranges itself when the base changes. The base order is **administered, not derived** — not alphabetical, not creation order.

**Audit splits on the existing line.** A role default edit is a configuration change and is audited; a user changing or resetting their own personalisation is not. A role default edit is **the first configuration change with no live blast radius**, so it needs none of the two-seam transaction.

## 11. Announcements

**An announcement is an ordinary transmission, and a service principal is a talker** ([ADR-0029](../adr/0029-an-announcement-is-an-ordinary-transmission.md)). Text arrives over HTTP on the token path, the server synthesises it on the box, and the audio enters the media plane as a producer where the ordinary fan-out carries it. Recording taps it per (talker, loop) for free, attribution is the bound role, loudest-wins applies, and the audience computation already knows who will hear it.

**A service principal never carries media over the network at all** — no WebRTC, no ICE, no DTLS, no client.

### The call

- **Text plus an explicit list of loops.** No wildcard, no *all*, and an empty list is a refusal.
- **A loop the bound role cannot reach refuses the whole call** — deliberately the opposite of the preset rule. A preset is shared across occupants of differing reach so silent narrowing is the only way it can work; a service principal has exactly one bound role, so an unreachable loop is a configuration error, and partial delivery would let a misconfigured script appear to work for months.
- **Accepted or refused synchronously, and nothing after that.** No delivery status, no callback, no outcome record.
- **One principal is one uplink**, so its announcements serialise. Different principals may overlap, exactly as two humans may. **An announcement is refused when the backlog would delay it past ~30 seconds**; a maximum length is capped for the same reason. A per-request deadline was rejected as caller surface for a problem the server sees better.
- **The source prefix is server-composed** from the bound role and prepended — `"Ground Alarms: evacuate"`. The caller supplies the body only and can neither set nor suppress it, because a caller that could set it could announce itself as `Flight Director`.
- **Carries a priority flag**, set per announcement. The priority is audited even though the announcement is not.
- **Additive, ducks nothing, overrides nothing** except the subscriber's own attenuation when flagged priority. **`control` plays no part in announcements at all.**
- **Not audited on the token path** — an announcement is traffic, and traffic is recording's business. **The admin console's page is the exception** and is audited with its text ([§9](#9-the-admin-console), [ADR-0067](../adr/0067-composed-text-is-a-decision.md)).

### Synthesis

**A long-running loopback sidecar**: text in, 48 kHz mono PCM out — the format everything is encoded into anyway ([ADR-0030](../adr/0030-speech-synthesis-is-a-swappable-sidecar.md)). A subprocess per announcement was preferred until the model-load cost showed up: every candidate engine loads a neural model at startup, roughly a second, paid every single time.

**The engine is not pinned; its licence posture is** — permissive only, Apache-2.0 or MIT, because a licence is not cheaply reversible once a customer has the box. Kokoro-82M is the current candidate. Piper is a legitimate substitution for a customer who wants it, but active Piper is GPL-3.0 since `rhasspy/piper` went read-only in October 2025 — a sidecar-only engine, which the seam makes painless.

**The whole clip is rendered before emission begins**, so the duration is known before anything goes on air (which is what makes the backlog computable) and a failure happens off-air rather than halfway through a sentence.

**One voice, hardcoded.** No per-role voice, no per-request selection — a caller that could choose a voice could choose one that sounds like a human position. **SSML is not accepted.**

**One deployment-wide pronunciation dictionary**: literal whole-token replacements, longest match wins, applied left to right, to **the whole composed string including the role prefix** — role names are acronyms too. Regular expressions were rejected: one bad pattern would make every announcement in the deployment unintelligible at a moment nobody is testing.

### v1 injects; it does not schedule

**No scheduler, no watchers, no condition evaluation.** No schedule CRUD, no timezone handling, no missed-fire semantics, no admin screen for any of it. VoxLoop offers *speak this now*; anything deciding *when* lives outside it, and a cron job posting to the endpoint is the whole intended answer ([ADR-0031](../adr/0031-v1-injects-but-does-not-schedule.md)).

**This is a conscious divergence from the brief and must be stated to the pilot customer as a gap**, not concealed behind *the API is generic*.

## 12. Audit

**The audit log records decisions, not traffic** ([ADR-0028](../adr/0028-the-audit-log-records-decisions-not-traffic.md)). Append-only, queryable, surfaced in the admin console, **filterable by actor and by target**. Three classes and no more:

- **Authentication events** — sign-in success and failure, sign-out, session start and session end with reason, enrolment, password reset, service token issue and revocation.
- **Configuration changes** — user, role and loop creation and deletion, eligibility grants and revocations, permission cell changes, role default edits, pronunciation dictionary edits — each with **before and after plus the blast radius**.
- **Operational authority acts** — Cut, forced takeover, forced relinquish, monitoring directives, and **every priority key press** with no minimum duration.
- **Console announcements** — an administrator speaking as the console principal, with the text, the loops, the priority flag, the bound role and the clip duration ([ADR-0067](../adr/0067-composed-text-is-a-decision.md)). The only content the log holds, and the only place the acting administrator is recorded at all.

The actor is the **internal user id**; for authority acts the **role and the authority loop** as well, because the role is the source of the authority and the loop is what scopes it.

**Keying is deliberately excluded** and belongs with recording. Mixing them buries a handful of permission edits per month under thousands of keying events per shift, which is how an audit log stops being read.

**Refused authority acts and refused administration writes are audited. Refused reads are not** — a denied read is usually a stale browser tab.

**Announcements on the token path are not audited**; a priority announcement from a script produces an entry for the *priority*, not the announcement. **The admin console's page is the exception**, audited as one entry covering both, because its decision is the use rather than a token grant made months earlier. **Hails are not audited** — a hail grants nothing and is shed with one click.

**Composed text is a decision; captured audio is traffic.** That is the line admitting an administrator's typed sentence into the log while keeping every open microphone out of it, and it is the line any later proposal to log content has to clear.

**Append-only is an application discipline, not a database guarantee**, so it must be *tested*, not merely intended. **The audit log outlives the records it references** — deleting a user must not orphan their entries, so an entry stores the internal id *and* a snapshot of the name as it stood.

**Reading the audit log is a system-administration capability**, not an operator-console feature.

## 13. Architecture and deployment

The reasoning is in the ADRs; the enumeration of parts is [`modules.md`](./modules.md). What follows is what an implementer needs to hold in their head.

### Media

**mediasoup, self-hosted, first-party Rust API. VoxLoop owns the signalling** ([ADR-0006](../adr/0006-mediasoup-carries-the-audio.md)). Signalling, presence, reconnection and permission enforcement are VoxLoop's code — the price of an auditable permission boundary, and a decision surface a product SFU would have absorbed. One Worker, one Router, **no TURN**, a single shared `WebRtcServer` port (UDP primary, ICE-TCP fallback on the same port).

**Three layers, and only the middle knows what a loop is** ([ADR-0007](../adr/0007-the-client-emits-one-stream.md)):

| | |
|---|---|
| **Uplink** | the talker's client encodes once and sends **one** stream, whatever they are armed on. It transmits; it does not address |
| **Server** | fans that stream into each loop the talker is armed and keyed on. The only place loop identity exists in the media path |
| **Downlink** | one stream per **audible talker**, mixed in the client at per-loop volume |

**A loop is not a transport primitive.** Router-per-loop is rejected — a Transport belongs to one Router, so a user monitoring six loops would need six ICE and DTLS sessions, which is the connection explosion arriving through a different door. Publishing one stream per destination is rejected: it makes the client encode N times and turns arming into a renegotiation. Server-side mixing is rejected: it forecloses per-stream processing permanently.

**The downlink is per talker, not per (talker, loop)** — the finer split delivers the same audio twice to anyone monitoring two of a talker's destinations, which is exactly the case multi-destination emission exists to produce.

**The media plane executes routing; it never computes it** ([ADR-0063](../adr/0063-the-media-plane-executes-routing-it-never-computes-it.md)). The state authority computes the audience and hands the answer down. No subscription, arm set or permission rung crosses into the media plane; a loop identifier crosses only as an opaque label. **Cut is a state authority act**, not a media plane one — the authority withdraws the audience and the media plane executes the result. This is what makes every routing rule testable with no worker running.

**The recording seam**: a `PlainTransport` per (talker, destination loop), `enable_srtp: false`, `rtcp_mux: true`, on a loopback address and port allocated per loop, **created only when a sink attaches** ([ADR-0009](../adr/0009-recording-taps-plain-rtp-on-loopback.md)). It carries **encoded Opus, not decoded PCM** — decoding in the media server would put permanent per-loop DSP load on the box for a feature that is not in v1. **The sink owns decoding.** The bus is **loopback-only**; moving a sink off the box is a new decision with its own authentication, never a configuration change.

### The stack

**Rust on axum and tokio, one SQLite file, all live state in process** ([ADR-0036](../adr/0036-the-backend-is-rust-on-axum.md)). The language was taken deliberately rather than inherited: the code this governs is permission evaluation, connection-state ladders, emission enforcement and the presence document, where the failure mode is an open microphone nobody was told about, and exhaustive matching over the rungs, the ladders and observed-versus-asserted provenance is the class of bug Rust removes by construction.

The tax is written down: cargo treats every `0.x` minor bump as breaking, so **the mediasoup crate is pinned exactly** and an upgrade is scheduled work with a changelog read. **mediasoup's callbacks fire on mediasoup's threads** — the bridge into axum is channels, never a blocking call or a borrowed tokio handle.

**`tracing` is the logging facade**, chosen early so observability is a wiring job rather than a retrofit.

**The client ships as static assets embedded at release** ([ADR-0037](../adr/0037-the-client-ships-as-static-assets-embedded-at-release.md)). SvelteKit with `adapter-static`; **no Node runs in the deployment**. The embed is behind a **Cargo feature**, off by default and on for release, and **`web/dist/` is not committed** — Vite content-hashes, so committed output grows unboundedly, and stale output silently ships the wrong console. A release build has an ordering requirement: `npm run build` before `cargo build --release --features <embed>`.

**Persistence: one SQLite file in WAL mode, behind domain-shaped repository traits** ([ADR-0038](../adr/0038-sqlite-behind-domain-shaped-repositories.md)) — `set_cell`, `grant_eligibility`, `record_authority_act`, not `query`/`execute`. **`sqlx::Any` is ruled out by name**: it looks like it *is* the seam and is not. Offline query metadata committed, migrations embedded and run at startup, and **the binary refuses to start against a schema newer than it knows**.

**The transaction is part of the seam.** A grid edit reads the cell, computes the blast radius over **live** sessions, writes the cell and writes the audit entry. The blast radius is computed on the live side and **passed in as a value** before the transaction opens, so neither seam knows about the other. The corollary is accepted: **the audit log shares a store with the configuration it audits.**

**Live state is in-process behind one state authority** ([ADR-0039](../adr/0039-live-state-is-in-process-behind-one-state-authority.md)) — sessions, occupancy, subscriptions, arms, key state, connection state, media path state, beacon counts, audience projections. **The single writer**, which is what makes presence versions monotonic and documents atomic. It holds nothing durable, and it is deliberately **not** modelled as key-value, because a presence document is a projection rather than records.

**Redis is hygiene, not a migration path.** Both motivations fail: surviving a restart is unavailable at any price, and running two servers is foreclosed by the media plane rather than by the state store.

**Therefore a restart ends every session.** The Worker is a child of the process and every transport dies with it, so persisted occupancy would describe roles held by sessions with no audio path. Users stay **signed in** and must **assume** again; every loop's honest staffing state afterwards is `vacant`. **Upgrading the binary during an event has a real cost, and since configuration is read once at startup, so does renewing a certificate.**

### Modules and seams

Eleven modules, seven in the binary and four in the client bundle ([`modules.md`](./modules.md), [ADR-0060](../adr/0060-a-seam-names-domain-operations.md)).

**A seam's interface names domain operations and domain types, and nothing on the caller's side can tell which adapter is behind it.** The test is mechanical: if a type or an error crossing the interface names the mechanism, the seam has failed.

**Audit is not a module** — it folds into Configuration, because an entry and the write it records commit together, and a separate module is one you can forget to call. **Persistence is not a module** either; it is Configuration's seam, and nothing else in the system reaches a database.

**Module privacy is the enforcement** ([ADR-0061](../adr/0061-module-privacy-is-the-seam-enforcement.md)). One binary crate, no workspace: Rust's module privacy already enforces seams inside one crate, so the compile-time enforcement is free. **Each module makes exactly its interface `pub(crate)` and everything else stays private.** Widening `pub(crate)` is the cheapest edit in the codebase and it is how a seam quietly stops existing. Split into a workspace when a module gains a consumer outside the binary, and not before.

The client gets **one lint rule, on Input alone**, because Input is the only seam with real variation and the wrapper's promise needs a failing build behind it.

**The call graph is acyclic** ([ADR-0062](../adr/0062-the-call-graph-is-acyclic-and-effects-modules-are-sinks.md)). **Media plane and Synthesis are sinks**: they call nothing and report on channels. A sink cannot refuse, so a caller never learns from the call whether the effect succeeded — which is why a dead sidecar loses every announcement silently, and why the binary supervises both subprocesses so their health is observed rather than returned. **A cycle is a design error, not a refactor.**

**Tests run against the real store** ([ADR-0064](../adr/0064-tests-run-against-the-real-store.md)). A fake exists at exactly two seams, Media plane and Synthesis, and both are recorders rather than simulations. **An in-memory repository is ruled out by name** — it does not enforce foreign keys, does not have SQLite's type affinity, does not serialise writers the way WAL does, and its failure mode is that the tests pass while the product is broken. A test opens a temporary database, migrates it, and throws it away.

**Consequence to hold onto: the repository seam will never get a second adapter**, and nor will Identity or the recording tap. Those traits stay permanently unexercised. Accepted knowingly as the price of not shipping tests that pass while the product is broken. **Nobody should build a fake repository later thinking they are fixing an oversight.**

### The client

**One SvelteKit application, browser-first and first-class on every platform including Linux** ([ADR-0020](../adr/0020-the-browser-is-the-client.md)). Any modern browser — `mediasoup-client` ships Firefox and Safari handlers, so there is no Chromium lock-in.

**The Tauri wrapper is the same artefact with one extra input source registered at startup**: a native global hotkey. It is the **last piece of v1 work**, attempted only once the web product is built and Ed is happy with it. Targets Windows and macOS; **only Windows is supported**, macOS existing purely so the hotkey path has a local test loop.

**The wrapper may only ever add a source to the seam.** Needing a second code path anywhere else — different signalling, different audio, different UI — means the one-client story has broken, and that is the signal to stop rather than to fork the shell. It uses the webview's own cookie store and does nothing custom.

**Windows `RegisterHotKey` is exclusive**: a global hotkey *takes* a key from the telemetry application rather than sharing it, and registration **fails rather than warns** when the combination is claimed. **Binding-time conflict detection is mandatory**, three times over, and priority is the binding an operator is least likely to have exercised before the moment they need it. The wrapper's hotkey cannot default to a bare `` ` ``.

**Consequence to hold onto: v1 has no unfocused push-to-talk until the wrapper lands.** The trigger that makes it mandatory rather than optional is the first pilot user expected to work a shift with telemetry focused.

### Deployment

**Four moving parts** ([ADR-0040](../adr/0040-one-binary-one-unit-four-moving-parts.md)): the **Rust binary** (console, API, signalling, enforcement, TLS), the **mediasoup C++ worker**, the **text-to-speech sidecar** with its model file, and **one SQLite file**. The worker is **linked into the binary and runs on a thread of it** rather than beside it as a child process ([ADR-0070](../adr/0070-the-mediasoup-worker-is-a-thread-of-this-process.md)), so what ships is three artefacts rather than four.

**The binary supervises the worker and the sidecar; systemd supervises the binary.** One unit file. The sidecar is a subprocess and the worker is a thread, so supervision is a pid for one and `Worker::on_dead` for the other — the health of both is **observed rather than returned**, which is the rule that did not depend on where either of them lived.

**TLS terminates in the binary via rustls.** HTTPS is mandatory even on a LAN, because a `Secure` cookie is not sent otherwise. A reverse proxy is rejected as a fifth moving part and a second place a WebSocket upgrade can be misconfigured. **Where the certificate comes from is not settled** and belongs with deployment work — but configuration is read once at startup and a restart ends every session, so **renewal is a scheduled maintenance act**, which argues for a long-lived internal CA certificate over anything short-dated.

**Configuration splits on auditability.** Console-editable ⇒ **database** (users, roles, loops, grid, eligibility, service principals, pronunciation dictionary, role defaults, base loop order). Needed-to-reach-the-database ⇒ **a TOML file with environment-variable overrides**, read once at startup (listen ports, certificate paths, mediasoup's announced address and port, the sidecar's loopback address, the SQLite path, log level, the four reconnection timers).

**Firewall**: one inbound TCP port for HTTPS and the signalling WebSocket, one inbound UDP port for media with TCP on the same port.

**The box is the database**, so backup is a real obligation. **A restart is indistinguishable from total network loss to every client**, so alerting must not read a deliberate upgrade as a mass outage.

**The shipped artefact set** is a binary with the worker inside it, a sidecar with its model file, one unit file and one TOML file. Building it needs a C++ toolchain and Python as well as Rust, because the worker is compiled from source at `cargo build` time. Signing, installation and the update path belong to the deployment and packaging work.

## 14. Load tests and measurements before v1 is called done

These are open obligations, not design questions.

- **~3,000–4,000 allocated consumers on one mediasoup Worker.** ADR-0006's affordability argument rests on an idle consumer being nearly free, which mediasoup does not document. **Include beacon traffic** — it is the one always-on packet source and therefore the floor under the idle-consumer assumption.
- **The latency budget on the pilot's actual network, including a VPN client.** No research pass addressed VPN latency for any candidate transport.
- **The `disconnected` threshold tuned against the pilot's VPN.** It is a safety parameter: it sets how long a hiccup can silence the loudest voice in the room.
- **G.114's band structure is cited from memory and is telephony-shaped rather than intercom-shaped.** Verify before leaning on it in anything customer-facing.
- **Default-output-device swap detection** is asserted at moderate confidence and should be confirmed on real hardware.
- **`unreviewed`, rename safety and append-only need tests.** A stray join on username works perfectly until the first rename; append-only is enforced only by there being no code path that updates or deletes an entry.

Ruled out deliberately. **An implementing agent must not helpfully add any of these.** Where "don't foreclose it" appears, that is the only obligation v1 carries.

| **Staffing requests** — *somebody go and be the Thermal Engineer* | A hail reaches a **seat**, so a vacant role is unhailable. A genuinely different feature: its audience is the lobby, and it needs the eligibility model to answer *who is qualified and idle* |

| **Named profiles** | The role is the profile. Bringing them back needs an argument against role assumption, not merely a use case ([ADR-0049](../adr/0049-the-role-is-the-profile.md)) |
| **Enforced minimum subscriptions** | Rejected, and worse than an enforced directive because it would carry no `control` gate at all |
| **A per-user permission exception of any kind** | No exception layer exists, and there never will be one |
| **A forceful announcement endpoint** | Designed, then dropped — forcing audio into someone's ears is operational authority, at which point it becomes a second mechanism for compelling people beside monitoring directives |
| **A reply channel of any kind** | A hail gets no reply. It would be VoxLoop's first person-to-person message |
| **A deployment-wide roster or shift board** | The hail picker is loop-anchored and is the only place the console names a person |
| **Reading or resetting another user's personalisation** | The reset button is the support answer |
| **Optimistic rendering** | Reopening [ADR-0016](../adr/0016-displayed-state-is-observed-or-asserted.md), not making a UI tweak |
| **An in-memory repository fake** | The alternative that was rejected, not an oversight ([ADR-0064](../adr/0064-tests-run-against-the-real-store.md)) |

## 16. Accepted gaps

Known, deliberate, and stated here so they are not discovered. Several should be said to the pilot customer.

**Voice and reach**

- **VoxLoop cannot guarantee that anyone hears anything, and never will.** It guarantees only that a subscriber who is subscribed and unmuted will not have their own attenuation hide a priority transmission.
- **Mute defeats everything** — an announcement, a monitoring directive, a hail, a priority transmission. Softened only by a muted staffed loop dropping to `away`, and by talking indicators surviving a mute.
- **An announcement into a vacant or wholly-muted loop succeeds silently** and the caller never learns.
- **Nothing in VoxLoop can compel a subscription to be kept.** [ADR-0005](../adr/0005-occupancy-means-listening-not-signed-in.md) named a tool for it and [ADR-0035](../adr/0035-a-monitoring-directive-promotes-a-loop-it-does-not-police-it.md) removed it. If one is genuinely needed it must be designed against the finding that compulsion is unavailable at any price.
- **There is no proportionate sanction for airtime abuse.** The brief's *kick them off that loop* has no v1 answer: the escalation is Cut, then forced relinquish, then account lock, and nothing sits between them because the thing that would is a persistent per-user deny. Mission-control practice handles this by voice and through the shift lead.
- **An ungated priority key can degrade to nothing.** If everyone uses it always, priority means nothing; the only safeguards are social pressure, the audit trail and Cut. The mark rendering everywhere at least makes the decay visible on consoles rather than only in a log.
- **A sub-second priority press can leave no trace on any console.** The audit log is the only record.
- **v1 cannot promise a conversation is private and does not pretend to.** Anyone whose role holds `monitor` hears it and the talkers cannot see who; the only tell is the transmit bar reading `4 hearing` when you expected one. Operator documentation should say this plainly.
- **Latch ships with no sidetone, expiry or alarm.** A latched open mic is judged a UX affordance rather than a safety-critical failure — no worse than an open microphone in a video call. Two mechanisms already stand: a latch dies after ~2s of `unconfirmed`, and Cut lets authority stop it.
- **The hot-latch banner holds only while VoxLoop is visible.** v1 has no unfocused PTT, so a latched operator is looking at the console by definition. **The Tauri wrapper is what breaks that assumption**, and a non-visual latch indication is what it will need.
- **A hail carries no guarantee of attention**, and nothing reports whether it was seen. A hail into a seat vacated between fetch and click reaches nobody, silently.
- **The receiver is never told where else a transmission went.** Every candidate signal either leaks loops outside their reach or reads as complete when it is not, and every reply is loop-addressed anyway. Compensation is entirely on the emitting side.

**State**

- **Beacon arrival does not prove you would hear a given talker.** Beacon *loss* proves deafness; the converse does not hold. The fault this leaves is a green console and an operator hearing nothing — the single failure this product can least afford.
- **A loop can read `away — not subscribed` indefinitely.** A staffing role whose occupants never subscribe leaves the loop reading `away` forever, and nothing forces it closed ([ADR-0065](../adr/0065-the-staffing-flag-reports-it-never-subscribes.md)). No seeding rule could, since the grid only ever narrows, and compulsion is unavailable at any price. An admin console check on the mismatch was designed and dropped: it reaches somebody who has to go looking, where the card mark, the reason and the lobby reach the person who fixes it in a click. **Nobody watches for it**, and a standing count of such loops is the obvious operations signal that does not exist.
- **A permanently dead media path never ends the session.** The operator holds their role, hears nothing, cannot key, and every loop they staff reads `away`, indefinitely. No media-side window is added: this is the one failure where the operator is present and reading a working console, so ending their session for them takes the decision from the person best placed to make it.
- **A single-occupant role is held by an unreachable ghost for 120 seconds.** The role shows its occupant unreachable with a running age; forced relinquish is the escape.
- **A restart ends every session**, and is indistinguishable from total network loss at the time.
- **The `impaired` threshold is a client-side judgement about a browser state**, so it cannot be tuned server-side and will behave differently across browsers. This is where a genuinely universal browser tier costs something.
- **The transmitting lamp costs one round trip to light**, and the console must not pre-light it.
- **The first moments of a priority transmission can play attenuated and unmarked**, because the attribute rides signalling and the audio does not.
- **Two service principals can talk over each other**, and neither will know. The same situation as two humans keying at once.

**Identity and administration**

- **Who is physically at a console is answered by occupancy, never by the credential.** With no absolute session cap, a console occupied indefinitely never re-authenticates and shift change becomes inheritance rather than an act. Accepted rather than solved.
- **Being able to read the server's logs is equivalent to being an administrator, at first start**, because the bootstrap code is in them.
- **The on-box CLI is a permanent privileged surface** that bypasses every authorisation check by design. **Shell access to the host is the highest privilege in the system.**
- **A stolen cookie is a full compromise**, with no second factor behind it.
- **A system administrator can speak on a loop no role they are eligible for can reach**, by granting the console principal `emit` and then announcing. Two clicks rather than a wall. Both acts are audited, and the transmission is attributed to the console role rather than to them ([ADR-0066](../adr/0066-the-console-announces-as-the-designated-principal.md)).
- **The audit log holds announcement text**, which is the only content in it and the only content anywhere in v1, since recording is a seam rather than a feature. Retention, export and tamper-evidence are unsettled for the log generally, and this is the part of it a customer will care about first.
- **Onboarding has an out-of-band step** — an administrator physically or verbally delivers an enrolment code. Fine at pilot scale; the first thing that hurts past one site.
- **A defective or compromised client can send audio while claiming to be unkeyed.** Bounded by the arm boundary and detectable via `AudioLevelObserver`.
- **Authority over a role that staffs no loop cannot be expressed**, since there is no loop through which takeover authority can reach it.
- **Audio device support requests cannot be answered from the server.**

## 17. What assembly found, and how each was closed

Assembling this spec surfaced three things asserted in one place and absent from every other. **Nothing here is open.** The section stays because each was a real contradiction and the closing argument is worth having in one place, so nobody re-derives it from the ADRs and reaches a different answer.

1. ~~**Does marking a role as a staffing role still subscribe its occupants to that loop?**~~ **Settled by [ADR-0065](../adr/0065-the-staffing-flag-reports-it-never-subscribes.md).** It does not. The flag reports and never subscribes; [ADR-0052](../adr/0052-a-role-default-is-a-starting-point-never-a-floor.md)'s role default is the only seed, and the hole ADR-0005's default was covering is answered by visibility rather than by a seeding rule that could not reach it — a fifth `away` reason, a second state on the card mark, and the reason carried in the lobby. What it does not close is now [§16](#16-accepted-gaps).

2. ~~**How does the admin console's type-and-go announcement page actually call announce?**~~ **Settled by [ADR-0066](../adr/0066-the-console-announces-as-the-designated-principal.md) and [ADR-0067](../adr/0067-composed-text-is-a-decision.md).** It is a second `SystemAdministration` operation the server executes as the designated console principal, sharing the token path's implementation and checking `emit` against the bound role. No token reaches a browser, so cookie-plus-token is never presented. The page may key priority, the call is audited with its text, and install seeds the principal and its role with no reach. Enumerated in [`api-surface.md`](./api-surface.md), written up in [§9](#9-the-admin-console).

3. **Role presets** were settled in [ADR-0013](../adr/0013-arming-is-independent-of-subscription.md) and then omitted from every later enumeration. They have been added to [`api-surface.md`](./api-surface.md) as system administration, which is what ADR-0013 says they are. Nothing else about them was ever in question.

## 18. Follow-on work, not v1

These are known, unspecified, and named so nobody mistakes them for oversights. Each is a decision nobody has made.

**Recording implementation.** The seam is settled; the sink, decode and storage format, retention, and per-loop reconstruction from per-talker streams are not. The seam carries *encoded* audio, so a recorder spec must budget Opus decode. The beacon must be excluded. Announcements are included, so recordings carry synthesised speech attributed to roles no human occupies — and since announcements are not audited, recording is the only place their text lands. **The stakes have risen three times over**: the console never renders attribution, never surfaces a transmission's reach, and cannot distinguish a priority press in the tapped RTP. **The recorder carries the entire answer to *who said what to whom*.** With all live state dying with the process, a recorder wanting loop context, arm sets, attribution or priority must capture them **as they happen** — after a restart there is nothing left to reconstruct them from. A sink is the deployment's **fifth** process, which is the line it has to justify crossing.

**Deployment and packaging.** Single VPS versus a box inside the customer network; how it is shipped, signed, installed and updated. The certificate story. Backup. Shipping the Tauri wrapper to Windows consoles with its bindings conflict-checked at install or first run, not at first use. Release engineering that reproduces a toolchain, not just a checkout.

**Audit log retention, export and tamper-evidence** — plus whether *reading* the log is itself audited. All four wait on the same missing fact: nobody has established the pilot customer's compliance posture. Tamper-evidence has to be reckoned against a plain file on a box where shell access is already the highest privilege. Retention now has a term nobody has measured: priority presses are audited with no minimum duration, so it is the first entry class whose rate is set by operator behaviour.

**Observability, operations-facing half.** The operator-facing half is done; logs, metrics and alerting are not. There is one unauthenticated liveness route and subprocess, disk and backup health on the admin console — neither is a metrics story. Three axes per session to read. **Something must watch the watchers**: a beacon generator that silently stops reads as every subscriber going deaf at once. **Beacon-loss alerting must be suppressed while connection state already explains the silence**, or every VPN blip pages twice. **Failed sign-ins and refused authority acts are the brute-force signal**, and nothing yet alerts on them. **A rate of priority presses has no home**, and hail volume is invisible by construction. Eleven named modules give `tracing` spans an obvious naming scheme.
